## External Knowledge / Fragrantica Cache Coverage

The Flutter app does not scrape Fragrantica directly. It uses the existing external perfume knowledge worker/repo boundary.

The runtime mocked external group must prove:

```text
Perfume not in catalog
-> external worker lookup
-> save profile into perfume_knowledge cache shape
-> recommend catalog-only alternatives
-> second same perfume request hits perfume_knowledge cache
-> no second external lookup
```

Key v3/v4 scenarios:

| Scenario | coverageFocus |
|---|---|
| `V3-EXT-081` | `external_lookup_first_time`, `catalog_only_external_alternatives` |
| `V3-EXT-082` | `perfume_knowledge_cache_hit` |
| `V3-EXT-083` | `last_external_profile_followup` |
| `V4-EXT-071` | `external_lookup_ambiguous` |
| `V4-EXT-072` | `external_lookup_failure_safe` |

## What This Suite Proves

- Capability coverage for `C001-C102`.
- Unique scenario IDs and unique message fingerprints across the 300-scenario matrix.
- Mocked external knowledge flow through the repo/worker boundary.
- `perfume_knowledge` cache hit behavior after the first external profile lookup.
- Catalog-only alternatives for external perfume profiles.
- No external perfume product cards.
- No external availability, price, or stock claims.
- Generated staff taste seed data with `staffUpdatedBy=staff_taste_patch_tool`
  is explicitly verified as neutral and cannot boost ranking, even when its
  status looks reviewed.

## What This Suite Does Not Prove

- Real Fragrantica/backend reliability.
- Real network latency or timeout behavior.
- Production Firestore rules.
- Production cache retention, TTL, or indexing behavior.
- Full 300 UI runtime stability in one long run.
- Real customer conversion or final UX quality.

## Logs And Artifacts Policy

- Use sanitized test artifacts generated by the current validation run only.
- Do not read existing Firebase/debug/production logs.
- Do not store raw user IDs, raw session IDs, secrets, prompts, or private customer data.
- UX review should inspect summarized artifacts and generated scenario results, not only pass/fail status.

## Guardrails

- Default mode remains metadata only.
- Real backend remains disabled by default.
- No production Firestore writes happen in this suite.
- External perfume profiles are scent anchors only.
- Product cards, price, stock, and availability remain catalog-only.
- `staff_taste_patch_tool` data must remain neutral even if its product status
  looks reviewed.
